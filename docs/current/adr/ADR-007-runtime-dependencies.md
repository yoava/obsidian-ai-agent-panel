# ADR-007 — Runtime dependencies: bundled and screened

**Status:** accepted (2026-10-12)

## Context

- Obsidian loads one `main.js` and one `styles.css`; a release ships those
  and `manifest.json` only (`.github/workflows/release.yml:40`). Anything
  bundled ships to every user under its own license and is part of what the
  community-directory review and a security reviewer read.
- Obsidian provides `obsidian`, `electron`, CodeMirror, Lezer and the Node
  builtins at runtime (`esbuild.config.mjs:24-39`).
- Mature libraries exist for what the plugin implements or needs: `diff`
  (jsdiff) for text diffs, `@modelcontextprotocol/sdk` for MCP,
  `cross-spawn` for Windows command shims, `markdown-it` for Markdown, and
  font and UI packages for the redesign's look
  (`docs/work/research/redesign-canvas/`).

## Options considered

### Bundled libraries that pass a screen (recommended)

- Less code to own, upstream fixes, and the redesign's fonts and visuals
  without hand-built equivalents.
- Each library adds bundle size, a license notice, transitive packages and
  an upstream that can be compromised; the screen and an ADR per library
  bound that.

### No runtime npm packages; small original modules

- Every bundled line is original and MIT; nothing third-party runs in
  users' vaults.
- The project writes, tests and maintains code a library already maintains,
  and builds the redesign's look by hand.

### Libraries loaded at runtime

- Smaller release assets.
- A CDN load is a network request of the plugin's own, and extra files are
  not release assets.

## Decision

Why bundled, screened libraries:

- Over no runtime packages: the owner admitted bundled libraries that pass
  the dependency screen on 2026-10-12
  (`docs/current/constitution.md:52-56, 96-118`). Original code stays where
  a library fails the screen or costs more than it saves; the library's ADR
  weighs that.
- Over runtime loading: the plugin "makes no HTTP request"
  (`docs/current/constitution.md:16`), and a release ships only `main.js`,
  `manifest.json` and `styles.css` (`.github/workflows/release.yml:40`).
- Why a screen: libraries bring trees (`npm view <package> dependencies`
  lists 17 direct dependencies for `@modelcontextprotocol/sdk` 1.32.1, 6 for
  `markdown-it` 15.0.2 and 3 for `cross-spawn` 7.0.6), and any package can
  be compromised upstream: `event-stream` 3.3.6 shipped a malicious
  `flatmap-stream` dependency that targeted a Bitcoin wallet (GitHub
  advisory GHSA-mh6f-8j2x-4483).
- Why permissive licenses only: the repository is MIT
  (`docs/current/constitution.md:55-56`) and `main.js` is one combined work,
  which GPL-3.0 §5(c) would require to be licensed as a whole under the GPL.
  OFL-1.1 is the one copyleft exception, for font files only: it lets a font
  "be bundled, redistributed and/or sold with any software" if its notice
  and license travel with it (condition 2), and its copyleft binds only the
  Font Software (condition 5).

How the plugin runs the constitution's screen for each package in a
library's production closure (`npm ls --omit=dev --all`), at the exact
version in `package-lock.json`, with evidence dated in the library's ADR:

| Screen item | Pass here | Evidence |
| --- | --- | --- |
| Mature | Version ≥ 1.0.0, not a pre-release or deprecated; a release in the last 24 months, or no open advisory and a maintainer commit or issue reply in that time; at least 100,000 weekly downloads; the version published 7 days or more before it lands unless it fixes an advisory | `npm view <package>@<version> version deprecated time`; `https://api.npmjs.org/downloads/point/last-week/<package>`; the repository |
| Security review | `npm audit --omit=dev` reports nothing; `npm audit signatures` verifies it; no `hasInstallScript` on a production-closure entry in `package-lock.json`; what it adds to `main.js` and `styles.css` uses none of DES-001 A9's network APIs, no `node:child_process`, `eval`, `Function`, `innerHTML` or `outerHTML` (A10), no remote URL load and no telemetry, checked through its imports and by reading its module initialization and the callbacks the plugin passes it; a hit passes only when the ADR shows the plugin's calls cannot reach it | command output; the import list; the diff of the built files, each hit reviewed |
| Risk analysis | At least upstream compromise, abandonment, a vulnerability in bundled code, a license change, and bundle size, each scored inherent and residual; the owner accepts the result | the library's ADR |
| Legal review | The `license` field, the LICENSE file and every file that reaches the bundle (vendored code, fonts) carry a license on the constitution's list, and an `OR` expression records the license chosen; the full license text and copyright notices, and any Apache-2.0 `NOTICE` text, ship in the asset the package lands in, generated by the build; a font ships unmodified (subsetting and format conversion modify it) unless its license reserves no font name | the published tarball at its lockfile `integrity`; the built asset |

Each admitted library also gets:

- An accepted ADR of its own, or a section in the ADR of the area it serves,
  with the screen's evidence, the size change of `main.js` and `styles.css`,
  and original code weighed as the other option.
- An exact `dependencies` entry in `package.json`, locked in
  `package-lock.json`, so `npm audit --omit=dev` (CI `npm run audit`) and
  `npm ls --omit=dev` cover what ships; a human reviews the lockfile change.
- An entry under *Bundled* in `docs/current/LEGAL.md`.

Every lockfile change in a production closure, Dependabot's included and
transitive ones too, re-runs the security and legal rows, the 7-day rule, the
notices and the size change in its pull request; a major version, a new
transitive package, or a license or maintainer change re-runs the whole
screen and needs the library's ADR rewritten and accepted again.

No library lands before its task has, with the owner's edits to the
protected paths: rewritten DES-001 A11 and its test (no `dependencies` in
`package.json`) to "every `dependencies` entry is admitted by an accepted
ADR"; extended the architecture test, which reads only `src/` inputs today,
to the bundled packages; added the license, notice and bundled-code checks to
`make verify` and the release workflow; and added a Dependabot entry for
runtime packages. Dev-only packages pass the same constitution screen; ADR-014
decides which ones the toolchain uses.

## Consequences

- The bundle's third-party list can grow; each entry costs an ADR, a
  lockfile review and a LEGAL entry.
- An upstream compromise can reach users at the next release; exact pins,
  the screen, human lockfile review and Dependabot updates bound it.
- The original modules stay: `src/diff.ts`, `src/mcp/server.ts`,
  `src/protocol/client.ts`, `src/edits.ts`. Replacing one with a library is
  that library's ADR.
- ADR-004, ADR-008, ADR-010 and ADR-016 weighed specific libraries as
  runtime dependencies; a proposal to adopt one of them re-argues that ADR.
